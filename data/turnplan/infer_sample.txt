## 任务说明
你的任务是分析当前对话上下文，并生成一个 TurnPlan JSON。

TurnPlan 顶层只允许以下三个字段：
- `task`
- `knowledge`
- `chitchat`

规则：
- 这三个字段的值必须是 JSON 对象或null。
- 请根据用户真实表达的意图生成结果。
- 如果用户同时表达了多个意图，可以同时填写多个轨道。
- 后续执行引擎一次只能处理一个轨道；如果你输出多个轨道，系统会再向用户澄清先处理哪一个。
- 不要输出额外字段。
- 只输出合法 JSON，不要输出 markdown。
- 最终答案只能是 JSON 文本本身，不要使用 Markdown 代码块包裹，例如以三个反引号和 json 开头的结构。

## Task 结构
当用户是在办理业务时，填写 `task`：

Task 对象示例：
{
  "commands": [
    {"command": "start_flow", "flow": "<flow_id>"},
    {"command": "resume_flow"},
    {"command": "resume_flow", "flow": "<flow_id>"},
    {"command": "cancel_flow"},
    {"command": "set_slots", "slots": {"<slot_name>": "<value>"}}
  ]
}

仅允许以下 task commands：
- `start_flow`
- `resume_flow`
- `cancel_flow`
- `set_slots`

流程命令语义：
- `start_flow`: 用户想表达非继续、接着、恢复刚才的业务”等全新的业务意图时使用，这是一开启业务流程指令
- `resume_flow`：用户表达“继续、接着、恢复刚才的业务”等意图时使用；指定业务用 `flow`，未指定则省略 `flow`。
槽位提取规则：
- 每个 flow 的 `slots` 是该流程唯一允许使用的槽位清单；
- `set_slots.slots` 的 key 必须从目标 flow 的 `slots` 中原样选择，禁止创造、改写或猜测其他 key。
- 用户当前话语中只要明确给出了目标流程所需的槽位值，就必须输出 `set_slots`，不能因为同时输出了 `start_flow` 而省略。
- 同一轮同时包含业务意图和槽位值时，先输出 `start_flow`，再输出一个 `set_slots`；
多个已知槽位合并到同一个 `set_slots.slots` 对象。
- 只提取用户明确表达的值，禁止臆造用户没有提供的槽位值。
- 示例：“我想查询订单A20260408001的物流信息”必须输出：
{
    "commands":
            [
                {"command": "start_flow", "flow": "logistics_tracking"},
                {"command": "set_slots", "slots": {"order_number": "A20260408001"}}
            ]
 }
可用 flows：
